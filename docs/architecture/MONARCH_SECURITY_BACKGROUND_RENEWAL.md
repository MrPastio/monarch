# Monarch Security: фоновая защита и управление

2026-09-08, Codex. Код: `fdd62ddb1af8df5288061e94503a142f5b9498ca`.

Цель владельца: восстановить работоспособность Security и обновить UX; постоянная работа после закрытия Monarch и запуск при входе в Windows. Доставлено в локальную установленную версию **0.3.0.23**. Предыдущая **0.3.0.22** сохранена. Это локальная development-сборка, не подписанный опубликованный релиз.

## Что изменилось

- Защита запускается отдельной задачей Windows с ограниченными правами текущего пользователя. Окно Electron и вкладка Security не владеют её временем жизни. Задача работает от батареи, без ограничения длительности; Windows перезапускает упавший фоновый host. Host восстанавливает завершившийся protector с задержкой между попытками.
- В подписанном состоянии отдельно сохраняются включённый автозапуск и намерение пользователя продолжать защиту. Ручная пауза не отменяется watchdog. Отключение из продукта сохраняет существующую проверку Security PIN и подтверждение Kernel. Пароль/PIN не передаётся в аргументах процесса или планировщика.
- Блокировки ОС обеспечивают одного владельца protector, host и переходов запуска/остановки. Ошибка целостности состояния блокирует запуск; повреждённые данные не сбрасываются ради успешного старта.
- Опрос датчиков выполняется тремя рабочими потоками; у каждого датчика допускается один незавершённый опрос. Медленный системный запрос не останавливает heartbeat остальных датчиков. Подписанные checkpoint, очередь событий и принятие решений остаются в основном потоке. При ошибке checkpoint восстанавливается, опрос повторяется с задержкой.
- «Работает» означает успешный опрос датчиков и свежий heartbeat совпадающего PID. Отсутствие связи, начало запуска, остановка, ошибка датчика и зависший опрос показываются отдельно. Уже отключённая защита Windows обнаруживается при первом опросе.
- Ручные проверки файла/системы имеют отдельный ограниченный процесс, идентификатор, время выполнения и отмену. Переключение вкладок и обновление интерфейса подключаются к той же проверке. Отмена завершает только дерево этого процесса. Фоновая защита продолжает жить независимо.
- Частичные результаты, ошибка парсера и недоступные проверки подписи не превращаются в заключение о безопасности файла. Фоновый режим и новые ручные задания не загружают LLM и не передают данные в облако.
- Новый обзор содержит восемь состояний датчиков, свежесть статуса, управление постоянным режимом и доступные проверки. Опрос интерфейса не сбрасывает ввод в настройках. PIN вводится в маскированном диалоге и очищается при закрытии. Сохранены мобильная ширина, клавиатура, reduced motion и тёмный glassmorphism.

## Границы и следующие обновления

- Автозапуск происходит при входе пользователя в Windows. Это не системная служба до входа; выход из учётной записи и реальная перезагрузка ПК в этом проходе не выполнялись. Длительный многодневный soak ещё не проводился.
- Security наблюдает за системой и применяет существующие правила/согласованные действия; успешная работа датчиков не является гарантией отсутствия вредоносного ПО. Полномочия Defender, привилегированной response-службы, Safe и Kernel не расширялись.
- Зависший опрос обозначается как проблема. Watchdog восстанавливает завершившийся процесс, но не убивает живой пользовательский protector по таймеру. Ручная проверка ограничена 150 секундами; её результат живёт в текущем backend runtime и не переживает полный выход из приложения.
- Задача Windows хранит точные пути установленной .23 и комплектного Python. **Перед удалением/заменой этих корней следующий обновляющий агент обязан перенастроить задачу на новую проверенную версию и проверить её readback.** Не удалять .23, её родительские каталоги, runtime или environment, пока задача ссылается на них. Интеграция автоматической смены пути фоновой задачи в общий update transaction остаётся следующим шагом.
- Чтобы открыть новый интерфейс, требуется обычный перезапуск установленного Monarch. Текущий открытый source Electron использует ранее загруженный backend; это не доказательство работы новой установленной UI-сессии. Фон уже включён для установленного приложения, второй source protector не запускался.

## Обязательные ограничения для следующих агентов

Не возвращать синхронный общий опрос датчиков, запуск защиты из renderer или зелёный статус по одному наличию процесса. Не отключать рабочую задачу в «очистке тестов» и не завершать Python по имени. Не сбрасывать подписанное состояние и не принимать новый baseline автоматически ради зелёной проверки. Не трогать Safe, ключи, пользовательские данные, .22/.23 и другие сохранённые установки. Не переносить тестовые пути/фиктивные PIN в рабочие настройки. Antigravity остаётся denied; существующий закрытый Codex Security scan и отклонённые validation runs не возобновлять в рамках этой работы.

Официальные основания для параметров задачи Windows: [контексты безопасности Task Scheduler](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks), [New-ScheduledTaskSettingsSet](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasksettingsset?view=windowsserver2025-ps).
