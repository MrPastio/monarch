# Memory 4.1, фаза 6: нужна ли памяти маленькая языковая модель — замер и решение

Дата: 2026-10-17. Автор: Claude Code. Решение: **не подключать**. Ядро памяти не менялось.

## Вопрос

Владелец разрешил генеративную модель для памяти «только если крайне не требовательная». Проверено, лучше ли она
нынешнего извлекающего способа в двух местах:

1. **Пересказ капсул** — `memory_v4._compact_scope`: сейчас `summary` = список первых 160 символов каждого из 40
   старых запросов. В промпт капсула попадает обрезанной до 600 символов (`memory_v4`, `ceiling = 600`).
2. **Нормализация/извлечение фактов** — `memory_facts.extract_learnable` (узкие шаблоны).

## Как мерили

- Набор синтетический, русский, без личных данных: `docs/plans/memory-llm-bench/`
  - `facts_ru.json` — 50 сообщений: 20 прямых утверждений, 14 перефразов, 16 негативов (фантазии, чужие факты,
    просьбы перевести/написать рассказ, временное состояние, здоровье, пароль).
  - `capsule_topics_ru.json` — 14 тем × 10 запросов + шум; 30 капсул по 15–40 запросов из 1–3 тем (seed 20261017).
- Оценка правилами (`bench.py`): факт засчитан, если совпала группа и в тексте есть все префиксы значения;
  лишний факт — ложное обучение. Капсула: покрытие тем по ключевым словам (всего и в первых 600 символах),
  попадание поискового зонда по стемам, «выдуманные слова» — содержательные слова, которых нет во входе.
- Модели: Qwen2.5-0.5B-Instruct Q4_K_M (469 МБ, кандидат) и, как верхняя планка, Qwen2.5-1.5B-Instruct Q4_K_M
  (1.07 ГБ). llama-cpp-python 0.3.30 из `oscar/.venv`, только CPU (`n_gpu_layers=0`), 2 потока, `n_ctx=4096`,
  temperature 0. Для фактов — JSON-схема ответа (`response_format`), закрытый список групп, 2 примера в промпте.
  Вариант «с защитами» — к выходу модели применены те же жёсткие фильтры, что у извлекающего пути
  (чувствительное, «если бы/представь», длина) и отброшены факты с выдуманными словами.
- Модели и сырые результаты: `E:\MonarchBench\memory-llm-20261017\` (не на C:).

Воспроизвести:

По видам: шаблоны берут 21/23 прямых факта и 1/15 перефразов; 1.5B — 8/15 перефразов, но 10/23 прямых.
Типичные ошибки 0.5B: копирует пример из промпта («Я живу в Варне» в ответ на пароль, усталость, вопрос о билете),
путает группы (родной город → город проживания, «люблю туризм» → hometown), переводит на английский
(«Artём», «baker», «djazz»), выдаёт факты из чужих и вымышленных фраз («Марс», «Омск» друга, «Игорь» из рассказа).

**Нормализация** уже найденных шаблонами фактов (25 штук): значение сохранялось у 22 до и только у 16 (0.5B)
/ 15 (1.5B) после. 7–8 из 25 переписаны с выдумкой: «Отвечай мне всегда кратко» → отказ «это может быть
неэтично»; «Пиши коротко» → «Владимир Путин» (0.5B) / «Имя: Александр Петрович, Город: Москва» (1.5B);
«кот Персик» → «Кот Персик по имени Ульяна». Нынешний `normalize_statement` значение не теряет никогда.

## Решение

Модель **заметно хуже** по качеству в обеих задачах и на порядки дороже, поэтому по условию задачи —
отказ, ничего не подключаем, компонент в memory-search не добавляем.

- Единственный плюс — 1.5B ловит часть перефразов (8/15 против 1/15), но это втрое тяжелее кандидата и при этом
  ложно учится на 4 из 16 негативов даже с защитами, а теряет половину прямых фактов. Для памяти, которую Оскар
  месяцами повторяет человеку, ложный факт дороже пропущенного (принцип `memory_facts`).
- Пересказ капсул моделью вреден: превращает список вопросов в выдуманные ответы. Список запросов остаётся;
  дешёвый вариант «по новизне» даёт то же покрытие при половине длины, но так как в промпт капсула и так
  режется до 600 символов, выигрыша в ответах нет — менять не нужно.
- Пересмотреть можно, если появится модель, которая на этом же наборе (`bench.py`) даст F1 фактов > 0.70 при
  ≤ 2 ложных негативах и 0 % выдуманных слов в капсулах, укладываясь в ~0.5 ГБ и CPU.

## Что замер нашёл в шаблонах — исправлено тем же днём

Замер вскрыл в `memory_facts` ложное обучение на просьбах о тексте («Напиши рассказ…: «Меня зовут Игорь»»,
«Переведи…: меня зовут Анна и я живу в Берлине») и почти нулевую полноту на перефразах (1/15). Исправлено без
модели, узкими правилами:

- просьба написать/перевести/перефразировать/придумать и «как будет / как сказать по-…» — фраза не о человеке;
  слова в кавычках от первого лица — чужая реплика, не читаются;
- глагол первого лица без «я» («Сейчас обитаю в…», «Терпеть не могу…», «Работаю…») считается утверждением о себе
  (прошедшее время — нет: «Мама переехала» не учится);
- новые шаблоны: «зовут меня X», «обитаю / живу теперь в», «мой родной город — X» (тире-связка не рвёт фразу),
  «тружусь/работаю кем/где» (но не «работаю над отчётом», «работаю на выходных», «работаю удалённо»),
  «по профессии я X» и расширенный список профессий (существительное, не «я фотографирую»),
  «владею немецким» (только язык), «у меня две собаки», «кот у меня есть», «мне нравится X» (не «твой ответ /
  этот вариант»), «ненавижу, когда …», «можно / давай на ты».

| Набор | До: P / R / ложных на негативах | После |
|---|---|---|
| `facts_ru.json` (50, по нему писались правила) | 0.88 / 0.58 / 2 из 16 | 0.97 / 0.97 / 0 |
| `facts_ru_holdout.json` (31, написан после правил) | 0.70 / 0.33 / 3 из 13 | первый прогон 0.95 / 0.95 / 1; после двух правок 1.00 / 1.00 / 0 |

Отложенный набор после двух правок («переводчиком» ловилось фильтром «перевод…», «работаю на выходных» считалось
работой) уже не чистый — следующую проверку делать на новых примерах. Остался промах «Кот у меня есть, Барсиком
звать»: имя во второй части, берётся только «Кот у меня есть».
