## 2. Voice — Упрощённый режим и быстрые provider-карточки

Статус: **source implementation + focused/live provider verification; packaged/installed/public
acceptance не заявлены**.

Implementation commits: `60fe53c`, `51f5cd4`, `f75c209`, `668b6b3`, `ae7df99`.

- Упрощённый режим включён по умолчанию и не передаёт неизвестную команду крайне
  нестабильному полному Voice автоматически.
- Resident Desktop ждёт локальную wake-фразу «Оскар»/`Oscar`, работает при скрытом главном
  окне, отмечает активный микрофон в трее и показывает отдельный прозрачный click-through overlay.
- Wake больше не ждёт завершения всей записи: resident Sherpa T-one отдаёт partial transcript
  прямо в bounded wake-filter. Чистый runtime-тест выявил реальные варианты модели `воска`
  (partial) / `воскар` (final); они и латинский `voscar` приняты только в начале реплики, без
  широкого fuzzy-match произвольного текста.
- При совпадении overlay и короткая фраза `Слушаю` / `Да?` / `Я здесь` запускаются немедленно
  через системный локальный TTS. Весь Simplified lane использует только `instant` SAPI-path:
  Qwen TTS не прогревается, даже если команда пришла сразу после wake; LLM не вызывается.
  Capture явно запрашивает echo cancellation/noise suppression/auto gain, чтобы acknowledgement
  не загрязнял продолжающийся one-shot запрос `Оскар, открой …`.
- Тишина больше не уничтожает и не пересоздаёт микрофон каждые восемь секунд. Resident capture
  сохраняет один `getUserMedia` stream; VAD сбрасывает только дешёвое состояние, а PCM/STT segment

  не входит в цикл `listening/error/restart` и закрывается после одного terminal результата.
- Реальные capture/PCM/STT ошибки получают bounded stage/code/message diagnostics без сохранения
  распознанной речи и завершают короткий сеанс вместо бесконечного автоматического повтора.
- Детерминированные команды без LLM покрывают приложения, сайты/ярлыки, время/дату,

## Правило накопления

Каждый следующий существенный проход `0.3.0` добавляет сюда:

- пользовательский результат;
- точные изменённые компоненты;
- уровень готовности: architecture / source implementation / packaged / installed / published;
- выполненные тесты и измерения;
- незакрытые риски и release gates.

Нельзя включать в готовый consumer changelog незакоммиченный или непроверенный workstream только
потому, что его файлы присутствуют в общем dirty worktree.
